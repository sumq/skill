# 攻坚能力的成长规则

## 提炼触发与最小记录

发生关键卡点、原解释被反证、绕行转为根因修复，或用户要求复盘时提炼。优先复用项目已有记录，不逐次记录普通命令。

```text
案例标识 / 领域 / 日期 / 环境：
条件、动作、预期、实际：
最后正确点 / 第一错误点：
主要假设及实验前预测：
实验、观察、证据位置：
得到支持与被排除的解释：
处理方式 / 实际验证 / 尚未排除的解释：
候选规则（触发 → 区分实验 → 条件行动）：
反例 / 对应已有模式 / 建议变更：
```

缺少原始证据时保留“记录声称”与“当前核实”的区别。不收集无关内容，不保存凭据。失败与未解决案例同样可保留，避免只学习成功故事。

## 规则准入

1. 先查是否已有同因模式。相似案例可增加证据，不默认增加指令。
2. 区分“处理后现象消失”“原因被证实”“能够跨域迁移”。一次改动伴随恢复不自动证明后两项。
3. 提炼可区分假设的观测方法及行动条件，不把补丁、固定延迟、特定工具或笼统口号升级为普遍原则。
4. 明确至少一个不适用或危险的反例。例如确认丢失时，未经幂等验证的重复提交可能产生更多问题。
5. 候选规则在来源案例以外验证后再考虑晋升；新领域的类比只标为推演。多个相同环境的复现并不等于跨领域验证。

模式可处于候选、试用、保留、已取代。每次更新可以是补证据、合并、收窄、降级或删除。无法改变实际诊断行为的内容不进入核心。

## 持久更新与长度预算

普通项目执行只生成项目内的候选记录；明确要求更新本 Skill 时才编辑全局内容。已有本次维护授权时自主完成必要编辑和验证，不逐文件请求审批。规则的自动应用不意味着持续自我改写，也不等于模型权重训练。

修改前保留可恢复旧版：使用目标目录已有版本管理，或在 Skill 目录外的指定版本存档中保存变更文件并记录路径。未改变的资源不用复制，默认加载内容里不积累历史备份。

- 主文件建议不超过 6,000 字符（含空白），属于维护预算而非平台限制；优先替换、删重、合并，再下放真正有独立触发的细节。
- 模式按触发条件检索，默认不读取全部案例；发现冲突回查对应证据。
- 易变工具知识独立维护并标日期；无效模式从活动索引撤下，保留历史证据指针。
- 正式更新交付版本、原因、修改/删除规则、支持和反对证据、验证结果及回滚位置；更新版本元数据。
- 不预先规定每个项目必须产出几条经验。没有新的可靠认识时不改动，短化也是成长。

## 效果评估

按 [评估案例](evaluation.md) 比较旧版与候选版。新 Skill 无旧版时可建立无 Skill 基线；尽量保持模型、工具、输入一致。评估材料和评分要点分开发给独立执行者，条件允许时保留未参与设计的真实任务。

观察定位边界所需工作、假设可区分性、证据强度校准、无效重试、根因误判、修复副作用和任务完成情况。不能只计尝试次数越少越好：安全停止和承认未知有时是正确结果。

重要或波动明显的结果多次验证。软件行为可用测试与产物核对，视频或设计改进需同条件对比及评价者反馈。结构合法、作者推演、独立行为测试和真实项目收益分别报告；未做的测试标记未执行，不自评“持续变强”。
