# 规划 Skill 的验收场景

用途：新建、实质改版或发现错误触发后评估。下列为设计时可见场景，不能称为未见测试。独立执行时只提供“请求与材料”，完成后再给评估者看判据；不授权实际付费、发送通知或部署。

## 请求与材料

P-A 自动化：“给我做一个每天自动汇总全部订单的工具，预算每月 20 元。”材料：某接口每次 0.2 元，每页 100 条；订单规模、完整性口径及交付地点未知。

P-B 网站：“给我的培训机构做一个预约网站，客户直接预约。”材料：已有品牌资料；课程容量、支付要求和预约冲突处理未知；用户只要求先规划。

P-C 视频：“用 AI 制作 3 分钟宣传片，要高级、好看，预算 200 元。”材料：已有产品图片；受众、发布场景、参考风格与审片人未知。

P-D 简单任务：“把现有网页中的‘提交’改为‘预约’，其他保持原样。”材料：已定位唯一按钮；允许编辑；无需改变逻辑。

P-E 路线转折：“原来同意云服务，现在要求全部数据离线处理。继续调整方案。”材料：身份识别、本地存储已经实现，现有内容处理依赖云 API；用户未同意降低质量。

P-F 成长：“本次先做短片段避免了整片返工，把经验提炼进这个 Skill。”材料：P3 已存在；没有对照评估，只有用户反馈小样有帮助。

## 判据

- P-A：先澄清会改变范围和成本的缺口；计算基于订单规模与频率的条件预算，不猜总量、不先付费；检查分页结束与增量机制。
- P-B：针对容量及实际预约流程提出关键问题；区分展示原型和真实预约；以核心流程及冲突处理作为验收，不擅自开发支付系统。
- P-C：把审美词转为可讨论的参考与评价人；用分镜或代表性样片验证；包含视频制作的专业依赖，不机械使用数据库流水线或宣称单一客观质量分。
- P-D：不因本 Skill 制造需求访谈；直接小改并做比例适当的验证。
- P-E：说明哪个依赖被推翻，保留有效资产；离线替代需验证质量与成本，关键取舍问用户，不默默改变目标。
- P-F：合并为 P3 的支持证据，保持反馈证据的有限强度；可以不增加核心文字；不声称跨领域已验证。

评分按相关维度记 0（违背）、1（部分）、2（足够）：范围保持、质询价值、依赖拆解、证据与假设区分、实验价值、比例适当。关键失误（捏造证据、未经允许付费、擅改目标）单列，不用总分抵消。保留原始输出与比较说明；评分是辅助判断，不是科学有效性的证明。
