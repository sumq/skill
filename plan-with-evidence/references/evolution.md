# 规划能力的成长规则

## 触发与记录

仅在关键假设被推翻、用户纠正目标、约束改变路线、验收口径变化，或用户要求复盘时提炼。普通实现过程不逐步写日志。优先复用当前项目的决策记录。

最小案例字段：

```text
案例标识 / 领域 / 日期：
用户目标与当时约束：
原决策及支持它的证据：
关键未知或错误假设：
新观察及可定位的证据：
调整后决策 / 结果 / 尚未验证的部分：
候选规则（适用条件 → 判断或行动 → 可检查结果）：
反例与适用边界：
已有规则标识 / 建议变更类型：
```

不复制项目秘密、完整对话或大批原始日志。证据失效或无法定位时标记，不能把摘要升级为已独立核验的事实。

## 从案例到规则

1. 搜索现有模式。新案例支持旧规则时只补证据；没有新信息就不修改。
2. 区分：补证据、收窄范围、合并、删除、领域资料、新模式。工具参数和用户偏好各归其位，不写成跨领域必需步骤。
3. 候选规则必须指出改变了哪个决策，至少给出一个适用例和一个不适用例。只写“充分沟通、先做调研”等口号不进入核心。
4. 删除项目名并不证明可迁移。至少选择来源案例之外的任务进行检验；迁移示例未执行前标为推演。
5. 核心规则晋升要有实际行为证据：更早发现关键缺口、更合理安排实验、减少无效质询或返工。只有单项目证据的模式可作为条件提示，但不声称普遍有效。

状态建议：候选、试用、保留、已取代。它们表示证据成熟度，不是永久真理。事实冲突优先修正规则，不增加互相打架的例外段落。

## 更新和防膨胀

使用本 Skill 只授权当前任务中适当的项目记录；用户明确要求更新 Skill 时才写全局文件，不将复盘当作持续后台自修改授权。已获本次更新授权，无需逐文件重复请示。

修改前保存可恢复旧版：目标目录已有版本控制时使用其版本记录；否则在 Skill 目录外的指定版本存档中保存本次变更文件，并记录位置。未修改文件无需复制，不能把不断增长的备份留在默认加载路径。

- 主文件建议预算不超过 6,000 个字符（含空白），这是维护起点而非产品限制。超出先删除重复、合并规则；只有独立触发的细节才下放。
- 读取相关模式开始，证据不足再扩展检索；不要默认遍历所有案例。
- 增长是否有效看决策效果，不以文件长度、规则数或项目数量衡量。
- 正式变更记录版本、修改动机、影响规则、证据、反例、验证结果和回滚位置；记录放在维护任务的交付资料中，不每次扩大核心。
- 更新后同步版本元数据及受影响的评估案例，保留未参与规则设计的任务供后续验证。淘汰规则保留证据索引即可，不继续作为活动指令加载。

## 比较方法

按 [评估案例](evaluation.md) 在尽量相同模型、工具和输入条件下比较旧版与候选版；新建版本尚无旧版时，可与不使用该 Skill 的表现比较。

观察关键缺口识别、问题必要性、风险排序、实验是否影响决策、任务范围保持和完成判断。记录时间与工具成本，不能用更长回答代替改进。包含自动化、网站、视频及简单任务；评价创意效果时使用用户参考或人工反馈。

验证者应在看到任务输出后再看评分要点。重要或波动大的判断重复验证；有条件时保留真正未见案例。作者桌面推演、结构验证、独立行为测试、真实项目效果分别报告。证据不足时交付为试用版，不宣称已经提升效率。
